# 次の候補と既知の課題

優先度は目安です。着手する前に、ユーザーと方針をすり合わせてください。

## 既知の課題・未確認の点

動作確認は、Node 上のモックを使ったテスト(`tests/smoke.mjs`)が中心で、テストは描画結果を見ていません。見た目と操作はブラウザで確認してください。iPad/iPhone での確認は実機で行っています。

- **ブラウザでの目視確認が必要**:特に、夜モードの明るさ、半透明にした水草の重なり、縦長画面の全画面表示。
- **エンゼルフィッシュのポップアップ**:餌を追って上へ泳ぐとき、長い背びれが枠の上で切れることがある。
- **iframe 内の全画面**:埋め込み先が全画面を許可していないと、代替モードになる(想定どおりの動作だが、見え方を確認したい)。
- **動きを減らす設定**:`prefers-reduced-motion` は UI の遷移にしか反映していない。水槽のアニメーション自体は減らしていない。

- **お掃除生体(issue #3)の実機確認**:iPhone/iPad での `?perf`(logic+draw と、`trail` の on/fading/off の切り替え)と、跡あり版の作り置き(ガラス用 2 枚+岩流木用 3 枚。DPR 1.5 の PC で約 9MB)のメモリは未計測。
- **オトが流木の上で細い棒に見えやすい**:横から見た細身の体が、細い枝に重なると棒のように見える。
- **ヤマトヌマエビのパネルのアイコンが淡く見えにくい**:半透明の灰〜薄緑の体が、パネルの背景に溶けやすい。
- **お掃除生体は水草の葉に這わない**:葉が揺れるため、位置を作っていない(流木・岩・ガラス・砂だけ)。
- **石巻貝のガラスへの移動はフェード**:同じ位置で消えて、ガラスで現れる(壁を這って渡る動きは作っていない)。
- **`npm test` の所要時間**:約 30 秒から約 80 秒に延びた(お掃除生体の 2 分間のシミュレーションなど)。短くしたいなら、シミュレーションの長さやフレーム数を減らす。

- **軽量モード(issue #6)の未計測・未確認**:全画面の値(想定機・通常ウィンドウは 通常 約 100ms → 軽量 約 40ms を計測済み)、iPad / iPhone での軽量モードの動き(水草の揺れ・魚の旋回が約 20fps 相当の更新になる見え方)、軽量モードで長時間動かしたときのメモリ(作り置きが約 20MB + スプライト約 2〜9MB の概算のみ)。
- **bench と通常の `?perf` の食い違い(40ms 対 50ms)の原因調査**:`?perf&bench=cum` の全層は軽量で約 40ms だが、通常のタブの `?perf`(軽量オン)の表示は約 20fps(≒ 50ms)だった。計測条件(bench は GOV.override・保存凍結・捨て時間後の定常、`?perf` はオーバーレイ描画や実際の操作)の違いなどを調べる。人間の判断で 20fps を合格とした。
- **通常モードは変えていない**:想定機では通常モードのままだと約 10fps。軽量モードは手動の切り替えのみで、自動の切り替え(起動時の判定・性能の自動判定)は人間の決定で採用しなかった。通常モードを軽くしたい場合は別の課題にする。
- **localhost で動作を確認するときのキャッシュ**:Service Worker がキャッシュ優先なので、`npm run serve` で変更を確認するときは Ctrl+Shift+R(強制再読み込み)が要る(古いキャッシュが残っていると変更が反映されない)。リリースは `npm run release` で `CACHE_VERSION` を上げる。
- **軽量モードの描き直しは 3 フレームに 1 回**:`LITE_EVERY`(`fish-render.js`)と `main.js` の `LITE_EVERY`(水草)で変えられる。大きくすると軽くなるが、動きが粗くなる。

## 対応済み

- **光の描写の負荷**(L1):コースティクスの毎フレームの画素計算と、光の筋・色調補正のグラデーション生成が描画の最大の負荷だった。作り置き方式にして、光の処理は軽くなった(ブラウザ実測でコースティクス 7.3→0.65ms、光の筋 7〜10→0.2ms。自動操作のタブでの粗い値なので、実機(iPad/iPhone)での再計測は未実施)。

- **Safari でのクリック判定**(T8):WebKit ではタップ由来の `click` の `pointerType` が "mouse" だったり無かったりするため、iPad/iPhone でアイコンをタップしてもポップアップが開かなかった。`click` の `pointerType` を使わず、直前の `pointerdown` の種別で判定するよう `bindPop` を修正した(マウスは従来どおり pointerenter/pointerleave)。実機(iPad/iPhone)で確認済み。
- **テストの所要時間**(T2):以前は 2〜3 分かかっていた。T2(ES Modules への分割)に伴い、vm で `<script>` を実行する方式から、グローバルにモックを置いて `js/main.js` を import する方式に変わり、約 30 秒(実測 21〜25 秒)になった(Canvas のモックの Proxy は今も使っている)。

- **時間の経過(issue #2)の確認の限界**:自動操作のブラウザのタブでは、実時間で進む変化(汚れ・苔・水草・溶存酸素)や日の出・日没での照明の切り替え、非表示/表示の切り替え(`visibilitychange`)を実際の時間で確かめられない。`?aging` で状態を指定して見た目を、テスト(`npm test`)で計算と保存を確かめている。実機の長時間の動作(数時間〜数日放置、ホーム画面アイコンからの起動・復帰)は未確認。
- **時間の進みが実時間 1:1**:ページを開いていてオンの間だけ進むので、短時間の利用では汚れや苔の変化が小さい(汚れが 1 になるまで 12 時間)。変化を見たいときは `?aging` で状態を指定する。加算する `dt` は実経過秒(上限 1 秒)なので、フレームレートが低くても 1:1 で進む(非表示で `requestAnimationFrame` が止まっていた間は、復帰時に 1 秒までしか数えない)。
- **テクスチャの初回生成で 1 フレーム引っかかる可能性**:汚れ・苔のテクスチャは、必要になった最初の描画(状態が 0.002 を超えたフレーム)で作る(遅延生成)。ガラスの汚れの画素計算(192×120)と苔の斑の描画で、そのフレームだけ数十 ms かかる可能性がある。実機(iPad/iPhone)では未計測。気になるなら、アイドル時に先に作る・小さく分けて作る。
- **岩の右側の苔の付着が弱め**:岩・流木の苔は、岩の輪郭の上面(法線が上向きの部分)にだけ付ける。ブラウザでの確認で、岩の右側の付着が左より弱く見える場合がある。付着の位置を輪郭の向きで偏らせないようにすれば改善できる(未対応)。
- **日の出・日没は東京固定**:ほかの地域で使うと、実際の明るさとずれる(人間の決定。位置情報には対応していない)。
- **iPad/iPhone のバックグラウンド**:ホーム画面から起動した PWA は、非表示の間は動かないので、閉じている間は反映しない(決定どおり)。実機で、非表示→表示でメンテの案内が出ることは未確認。
- **性能の再計測**:時間の経過の追加(毎フレームの `updateAging`・時計ボタン)と、汚れ・苔・水草の描画を足したあとの `?perf` の計測は、実機(iPad/iPhone)で未実施。

## 改善の候補

### 構成・開発環境
1. **モジュール分割**:実施済み。`js/` の素の ES Modules に分けた(ビルドツールなし)。魚の種類や器材を増やすときは、`species.js`、`fish-render.js`、`scene.js` などの該当モジュールに足す。
2. **見た目の回帰テスト**:Playwright で昼/夜・各水温のスクリーンショットを撮って比較する。乱数を固定できるよう、魚の初期配置にもシードを通す。
3. **テストの高速化**:対応済み(T2。所要は約 30 秒)。Canvas のモック(`tests/smoke.mjs` の `mkctx`)は今も Proxy を使っている。さらに縮めたいなら単純なオブジェクトに置き換える。

### 表現
4. 操作パネルとポップアップの枠にも、すりガラスのような半透明感を出す(第6段階で保留した案)。
5. 夜モードの LED の色温度を選べるようにする(昼白色・電球色など)。
6. 朝・夕の時間帯(昼夜の自動切り替えは issue #2 で実装済み:東京の日の出+1h〜日没+30m が昼。朝焼け・夕焼けの中間の色や、日の出・日没の前後でなめらかに明るさを変える表現は未対応)。

### 機能
7. 魚の種類を増やす(ベタ、ゼブラダニオなど。オトシンクルスは issue #3 で追加済み)。追加手順:`SPECIES` と `ORDER` に追加 → `PAINT` に描画関数 → `NOTES` と `POP_L` → テストの確認。
8. 餌やりを要素として加える(水質は issue #2 で、溶存酸素・水替え・フィルター掃除を実装済み)。
9. 水槽の中の魚をクリックすると、その魚の情報を出す。
10. 時間の経過の発展:日の出・日没を端末の位置情報から求める(現在は東京固定)/時間の進み方を選べるようにする(現在は実時間 1:1 のみ)/餌やりや水草のトリミングを手動の操作にする。

- **魚の U ターンは尾だけが曲がる(issue #7)**:胴も曲げるには、`PAINT`(`fish-render.js`)の変更が要る(今は表現の規則どおり `PAINT` の中身を変えず、`wag` を片側へ偏らせて尾だけを曲げている)。
- **chain の微増**:U ターンの導入で `npm run school` の chain が 1 ポイント弱上がった(シード間の幅の内側で、等方の目安 22% を下回る側)。悪化として扱っていないが、気になるなら群れの分離を見直す。
- **魚どうしの完全重なりの測定には 8 シード以上要る**:`tests/k0-measure.mjs` の「中心が体長の 0.15 倍未満」のフレーム数は、起動直後の配置に左右され、シードごとに 0〜575 とばらつく(3 シードでは判定がぶれる)。同じ位置に重なった 2 匹は、分離力がほぼ 0 になり、しばらく動けない(変更前からの仕様)。
- **お掃除生体の回る回数は減っていない**:折り返しの判断は従来のままで、回り方だけを U ターンにした。向きの食い違いが続く判定(`CRAWL.turnHold` 0.15 秒)以外に、回る頻度を抑える仕組みはない。
- **`npm run fishcheck`・`tests/crawl-continuity.mjs` は `npm test` に入れていない**(それぞれ約 3 分・約 4〜6 分)。魚やお掃除生体の動き・向き・描く位置を変えたら手で実行する。
- **層の入れ替えの判定は外接の正方形**:`FISH_R` は保守的な外接(軽量モードのスプライト用)なので、実際の魚の形より広く待つことがある。
