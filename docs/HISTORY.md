# これまでの経緯

claude.ai のチャットで作ってきた内容です。各段階の依頼と、そのとき決めたことを残します。

以前の公開先:claude.ai のアーティファクト(https://claude.ai/artifact/162zdJqm9DkE7nBha7HFcg)。現在は GitHub Pages(https://tomo1229-penghong22.github.io/aquarium/)で配信している(下の 10・11 を参照)。

## 1. 初版

**依頼**:熱帯魚の水槽。メジャーな魚を数種類、数と共に選べる。水草と温度計。水温は「少し冷たすぎる」から「放っておくとひどく弱る」までの範囲で調整。水草の揺れは自然に。やわらかい自然光が全体に当たる。

**決めたこと**
- 魚は6種。種ごとに適温と泳ぎ方(群れ・層・速さ)を変える。
- 水温は 18〜34℃。設定温度に向かって少しずつ変わる(ヒーターの熱慣性)。
- 低温は代謝低下で動きが鈍る(体調は下限 0.38 で止まる)。高温は溶存酸素の低下で水面に集まり、放置すると大きく弱る。
- 「時間の流れ」で体調変化だけを早送りできる。
- 水草の揺れは、ノイズを重ねた水流と、根元から先端へ遅れて伝わる波で表現。
- 光は光の筋とコースティクス。コースティクスは魚にも水草にも落ちる。

## 2. 全体を美しく

**依頼**:もっと美しく。ただし完全に写実的にはしない。

**決めたこと**:光と色の調和を重視した、少しイラスト寄りの方向。翡翠色の水、二層の光の筋、水面のきらめき、光の筋の中で光る粒子、奥のぼかした草原(空気遠近法)、流木とシダ、タイガーロータス、浮草、魚の縁の光とひれの筋、底に落ちる影。

## 3. 夜モード

**依頼**:今までが昼モード。夜モードを追加し、自然光を消して、水槽上部の白色 LED でライトアップ。

**決めたこと**:LED 器具を描き、真上からの青白い光、まっすぐ落ちる細い光の筋、くっきりしたコースティクス、下と端ほど暗い照明、暗い部屋。約 1.4 秒でなめらかに移行。器具は昼も消灯状態で表示。

## 4. 拡大ポップアップ

**依頼**:「魚を選ぶ」で魚にマウスオーバーしたら拡大表示。ごく自然に、ときどきユーモラスに動く。

**決めたこと**:小さな水槽の中で漂い、目はカーソルを追う。仕草は自然なものとユーモラスなものを混ぜ、種ごとの特技を用意(コリドラスのウインクは実際の習性)。擬音は控えめに。

## 5. ポップアップを閉じる不具合

**依頼**:マウスがアイコンから離れたらポップアップも消す。

**原因と対処**:名前の欄にも反応していたこと、クリックで残るフォーカスが表示を維持していたことが原因と考えられた。アイコンだけに反応させ、マウス由来のフォーカスでは開かないようにし、カーソルがアイコン外にあれば必ず閉じる判定を追加。

## 6. 半透明感

**依頼**:もう少し全体的に半透明感を。

**決めたこと**:対象は水槽の中の表現。魚は種ごとの透明度(テトラが最も透ける)、水草は奥ほど透ける。水を一段明るく澄ませ、霞と周辺減光を弱め、光を少し強めた。操作パネルは変更していない(すりガラス化は保留)。

## 7. 全画面モード

**依頼**:水槽に全画面モード。標準的な操作で切り替え。

**決めたこと**:ボタン・F キー・ダブルクリックで入り、Esc でも戻れる。縦横比に合わせて情景を作り直す。操作がないとボタンとカーソルを隠す。Fullscreen API が使えない環境では固定表示の代替モードに自動で切り替える。

## 9. ES Modules への分割

**依頼**:iPad/iPhone で、PC や LAN に頼らず単独で動かしたい。魚の種類や器材を増やしやすくしたい。

**決めたこと**:単一ファイル制約を撤廃した(claude.ai での公開をやめ、iPad/iPhone 向けに PWA として配信する方針)。`index.html` は マークアップと CSS だけにし、JavaScript は `js/` の 8 モジュール(素の ES Modules、ビルドなし)に分けた。ロジックと実行順は変えていない。分割前後で描画命令の列を記録して比較し(`npm run drawlog`)、完全に一致することで同一性を確かめた。`file://` では開けなくなったため、HTTP サーバ経由で開く。

## 10. PWA 化と GitHub Pages での公開

**依頼**:iPad/iPhone で、オフラインでもホーム画面から起動できるようにしたい。

**決めたこと**:`manifest.webmanifest`、`sw.js`(全ファイルの事前キャッシュ)、`icons/` を足して PWA にした。GitHub Pages(サブパス配信)に置くため、パスはすべて相対にした。ノッチとホームバーは `env(safe-area-inset-*)` で避ける。Jekyll の処理は無効にした。`?perf` で描画の区間ごとの所要時間を見られるようにした(iPhone では 95 匹でも 60fps、draw 約 4ms)。

## 11. 群れの修正・release・タップの修正

**群れ**:ネオン・ラミーの群れが数珠つなぎに見えたので、縦の散らばりを 0.6 から 1.0 に広げ、同種間の分離を進行方向の前後に長い楕円(1.3 倍)にした。速度がほぼ 0 のとき全同種から押される不具合は、基準速度の 10% 未満なら円形の分離に戻して直した。群れの形は `npm run school` で計測する。

**release**:`sw.js` の `CACHE_VERSION` の上げ忘れを防ぐため、`npm run release`(確認は `--dry-run`)で、確認・`npm test`・版の更新・コミット・push をまとめて行うようにした。

**テストの高速化**:T2(分割)に伴う副次的な効果。テストが、vm で `<script>` を実行する方式から、グローバルにモックを置いて import する方式に変わり、2〜3 分から約 30 秒になった(Canvas のモックの Proxy は今も使っている)。

**T8(タップ)**:iOS Safari でアイコンをタップしてもポップアップが開かなかった問題を、`click` の `pointerType` に頼らず、直前の `pointerdown` の種別で判定して修正した。実機で確認済み。

## 12. 24時間計の追加(issue #1)

**依頼**:水槽に時計を付けたい。

**決めたこと**:水槽の左下にアナログの24時間計を置いた。端末のローカル時刻で、0時が真上、時計回りに24時間で1周する。分針は人間の指示で不要とし、時針1本だけが分に応じて連続的に進む。描画順は温度計の直後、ガラスの前。`drawlog` は時計が現在時刻に依存するため、`TZ=UTC`・固定時刻 6:30 で実行するようにし、基準ログを取り直した。

## 13. 光の描写の簡素化(L1)

**依頼**:光の描写を今より簡素化して軽くする。ただし見た目は下品にならないように。

**決めたこと**:毎フレームの計算をやめ、素材を作り置きして貼るだけの方式にした。コースティクスは、周期化したテクスチャ 2 枚を別方向・別速度に流して `screen` で重ねる(以前は 150×90 画素を 2 フレームに 1 回 JS で計算していた)。光の筋は 7 本×2 層を 5 本×1 層のスプライトにし、グラデーションは作り置きして明滅は `globalAlpha` で行う。夜の全面合成は 4 回から 2 回(暗幕の乗算 1 回とソフトライト 1 回)、水面のきらめきは 46 個から 20 個、玉ボケはグラデーションの毎フレーム生成をやめてスプライト化した。筋ときらめきは乱数を元の個数ぶん消費し、以降の配置(玉ボケ・粒)が動かないようにした。方式の理由:画素計算を初回の 1 回に移せば、毎フレームのコストは `drawImage` だけになり、2 層を別方向に流すことで周期のループ感も出にくい。

**計測**:Node の CPU で光の処理は約 0.7%。ブラウザの実測ではコースティクスが 7.3ms から 0.65ms、光の筋が 7〜10ms から 0.2ms(自動操作のタブで測ったため粗い値)。見た目は人間が確認し、了承した。描画命令が変わるため、描画ログの基準は取り直した。

## 14. 時間の経過(issue #2)

**依頼**:現在の時間に合わせて、水槽の時間が自動で進む機能(オン/オフ可)。

**人間の決定**(2026-10-02)
- オン/オフは **24時間計のタップ/クリック**で切り替える。オフは時計をグレーにし、針だけ動き続ける。オンに戻すと、その時点の水槽の状態から再開する。
- 経過は **ページを開いていてオンの間だけ**、実時間と 1:1 で進める。閉じていた間は反映しない。
- 日の出・日没は **東京固定**。日の出+1 時間で LED を消し(自然光)、日没+30 分で点ける。手動の照明切り替えも可能で、次の切り替え時刻で自動に戻る。
- メンテ(水替え・清掃は 2 日ごと、フィルター掃除は 60 日ごと)は **実日付**で数える。期日を過ぎていたら「閉じている間(ページ非表示中・起動前)に実施した」扱いにする。開きっぱなしで期日が来た場合は、次に非表示になったときに実施する。
- 既定はオン。パネルに「水槽をリセット」ボタンを置く(2 段階確認、ダイアログなし)。
- 先に、光の描写を簡素化した(上の 13)。描画ログの基準の取り直しを 1 回にまとめ、この機能を新しい基準に対して「変化なし」で検証するため。

**実装**(タスクごとにコミット)
- **A1(状態モデル)**:`js/aging.js` を追加。汚れ・苔・目詰まり・水草の成長・溶存酸素・メンテ・東京の日の出日没(NOAA の式)。溶存酸素は、飽和量の式と、空気からの溶け込み・光合成・魚の呼吸・汚れの分解の収支で、係数は「新品・既定の魚で 7 以上、最大数でも 5 以上、最大数・34℃・目詰まりと汚れ最大で 3.5 以下」などの基準を満たすように決めた。保存は `aquarium-v1` に `aging` を足し、`core.js` に追加項目の登録口を設けた。
- **A2(時計・照明・リセット)**:24時間計の位置に透明なボタンを重ね、グレー表示(オフ)を足した。照明の自動化(段階が変わったときだけ切り替え)、メンテの案内、パネルの「水槽の手入れ」とリセット。**差し戻し 1 回**:ブラウザでの確認で、オフの時計が淡すぎて読みにくかったのと、フォーカスリングが時計の縁と区別できなかったため、オフの配色を濃い灰色に(針に明るい縁取りを足す)、フォーカスリングを二重の輪にして解消した。
- **A4(低酸素の行動と体調)**:低酸素係数を暑さ係数と `max` で合成して水面へ集まる動きに使い、`DO` < 3 で体調が下がる(適温でも回復しない、下限 0.04)ようにした。コリドラスの息継ぎも増える。
- **A3(見た目)**:ガラスの汚れ・苔、岩と流木の苔、水草の変化と、確認用の `?aging` パラメータ。ガラスは、薄い黄緑〜茶のむらのある膜とわずかな白濁(`dirt`)、下寄り・隅に多い緑の点(`algaeGlass`)を、水面の後・色調補正の前に重ねる。岩と流木は、上面をくすんだ茶緑のやわらかい毛玉と薄い膜で覆う(`algaeHard`。3 つの帯の重ね)。ソードは葉の縁に濃い点と、`clog` で外側の葉が黄ばむ。水草の成長は、ロタラが伸びて先端が赤くなり、バリスネリアが水面の手前まで伸び、浮草の葉が増える。テクスチャは別シードで、必要になった最初の描画で作る(新品で描画命令を出さず、描画ログの基準と一致させるため)。`?aging` は、指定した状態を保存しないよう aging の保存を凍結し、メンテも止める。
  - **差し戻し 1 回**:ブラウザでの確認で、流木の苔がトゲ状に見え、岩の苔がほとんど見えなかった。苔を細い線(うぶ毛)で描いていたのを、ぼかした小さな丸い毛玉と薄い膜に変えて解消した。
  - **`dt` の修正**:時間経過の `dt` に、ほかの更新と共通の 0.05 秒上限をかけていたため、20fps を下回ると実時間より遅れて進む問題があった。時間経過だけ、実経過秒(上限 1 秒)を使うようにした(非表示で `requestAnimationFrame` が止まっていた間は、復帰時に 1 秒までしか数えない)。

**描画ログ**:新品の状態では描画命令が変わらないので、基準ログは取り直さずに一致を確認した。

## 15. 酸素メーター

**依頼**:24時間計の右隣に、溶存酸素を示すメーターを付ける(人間のスケッチ:下が開いた弧と中心から伸びる針。酸素が減ると針が左回り。中を扇形に塗り、多い方から少ない方へ青→黄→赤)。

**人間の決定**(2026-10-02):文字は「O₂」だけ(数値・目盛りの数字は出さない)。時間の経過がオフでも通常の色で表示する(DO が凍結されるので針も止まる)。

**実装**:`js/scene.js` に `o2NeedleAngle`(針の角度。135° + 270° × DO/10)・`drawO2Meter`・`meterGeom`・`buildMeter` を追加し、`main.js` の `draw()` で時計の直後に呼ぶ。位置は時計の中心の 66U 右。色の位置は生理学的なしきい値(7 以上=青、4.5=黄(低酸素行動の始まり)、2 以下=赤(3 未満で体調低下))。文字盤は resize 時に作り置きし、毎フレームは `drawImage` と針だけ。扇形は `createConicGradient`(円錐グラデーションの位置は 1 周に対する割合なので、270° の扇形では DO の位置に 0.75 を掛ける)。ない環境では 2° ずつの分割塗り。
- テスト:`tests/smoke.mjs` に針の角度・全 DO での描画・位置・毎フレームの命令(グラデーション生成なし)を追加。モックに `createConicGradient` を足した(`tests/drawlog.mjs` も同様)。
- 描画ログ:見た目の変更なので基準ログを取り直した。取り直し前に、メーターの呼び出し(`drawO2Meter()` と `buildMeter()`)を外すと基準と一致すること、外さない場合の差分がメーターの命令(作り置き用のオフスクリーン 4 枚と毎フレームの描画 69 回)の挿入と、それに伴うオフスクリーンの通し番号の繰り下げだけであることを確かめた。

## 16. 魚が水槽全体を使って泳ぐ

**依頼**:魚が水槽の一部(横は中央寄り、縦は種ごとの狭い層)に固まらず、画面いっぱいに泳ぐようにする。

**人間の決定**(2026-10-02):縦横とも広く。種ごとの傾向(グッピーは上寄り、コリドラスは底)は弱めて残す。群れ(ネオン・ラミー)は今のまとまりを保ち、群れが水槽全体を回遊する。

**実装**(`js/fish-behavior.js`、`docs/SPEC.md` の「泳ぐ範囲」):
- 種の層を `[0.3a, b + 0.75(0.95 − b)]` に広げる(`baseZone`。コリドラスは底のまま)。個体の横の目標は体長に応じた余白(幅の 2% か体長の 0.6 倍)から反対側の端まで、群れの中心は幅の 5〜95%。
- 範囲を広げただけでは端へ届かなかったため、到着判定(体長の 0.3 倍)・壁の反発距離(0.6 倍)・個体の次の目標への切り替えの下限(`TRAVEL_K`)・群れの中心の速度上限(`CENTER_V`=1.0)・群れ度 0.5 以下の種の群れへの引力(0.15 倍)を調整した。
- 描画ログの基準は魚の位置が変わるため取り直した(変更を無効にすると旧基準と一致することを確認)。

**経緯と判断**:
- 群れの中心を壁・水面・砂から群れの半径ぶん離す案を試したが、最大数(S2)の群れの最近傍距離(nnMin)は戻りきらず、縦の広がり(ネオンの縦幅 0.65)とは両立しなかった。群れの中心の移動に時間加算を入れる案は、群れの平均速度が定まらないフレームを大きく増やしたため外した。
- 人間は「広がり優先」を選び、S2(最大数)の最近傍距離の悪化(ネオン 0.530 → 0.457、ラミー 0.754 → 0.664)を許容した。数値の目標は参考扱い。
- 最終の数値(12 シード × 140 秒):端 10% の帯は既定で左 1.5%・右 1.4%(変更前 0.2%・0.0%)、最大数で 2.6%・2.4%(同 0.5%・0.5%)。ネオンの縦 p5〜p95 幅は既定 0.601(変更前 0.469)、最大数 0.715(同 0.621)。「e<0.45 かつ θ<15°」は S1 ネオンで 0.12% → 1.09%。
